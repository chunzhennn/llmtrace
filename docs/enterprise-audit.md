# Enterprise session tracking audit

Reviewed the Rust proxy, trace pipeline, parsers, archives, SQL/query layer, plugins, authentication, and Svelte admin UI. This records the baseline gaps and the improvements in this change. It does not certify production capacity or invoice accuracy.

## Capability assessment

| Requirement | Baseline | After this change / remaining boundary |
| --- | --- | --- |
| Transparent HTTP/SSE proxy | Streaming upload/download, path/upstream allowlists, timeout/error capture, trace IDs | Preserved. Bodies are captured in memory up to configured limits. Oversized requests return 413; oversized responses continue with truncated captures. Cookies, control headers, and hop-by-hop headers are deliberately filtered. |
| Chat Completions, Responses, Messages | Basic text extraction from JSON and SSE | Reported usage, common function/tool-use calls, fragmented arguments, instructions, system prompts, and provider errors are parsed. Exotic output types and compressed `Content-Encoding` payloads are not comprehensively decoded. |
| Conversation contents | Complete captured wire bodies plus bounded text snapshots | Archives remain authoritative. Previews retain initial context and the newest turn and link to source requests. Repeated input histories are still repeated snapshots; no conversation DAG, deduplication, or full-content search. |
| Large sessions | zstd segments, metadata indexes, pagination | Fixed invalid PostgreSQL archive insertion order and unsafe filesystem rewrites. New immutable segments avoid growing-segment recompression. Large bodies load on demand in the UI. Added configurable size rotation and reference-aware archive cleanup. Cross-request compression/deduplication and object storage remain open. |
| Tool statistics | Most tool calls missing from parsed messages; no numeric fields | Common generated calls and arguments are stored, previewed, and counted. Historical input tool calls do not inflate generated-call counts. At most 128 generated tool previews are retained; overflow is tagged, so the count is a lower bound in that case. Tool execution happens elsewhere; its duration/success/cost is not inferred. |
| Token usage and costs | No native token or price accounting | Input/output/cache usage and integer micro-USD estimates are persisted and queryable. Per-session and per-user/model/key totals expose coverage. Pricing is configured per exact model; invoice reconciliation, multimodal/tool charges, calendar billing periods, and quota enforcement are not implemented. |
| User attribution | Plugin output supports user ID/name, but WASM has no network imports | Added opt-in exact-URL HTTP GET with deadlines, size/memory limits, and no redirects. Real gateway lookup schema and plugin mapping still need deployment-specific implementation. No shared lookup cache, retries, directory UI, or retrospective enrichment. |
| Session identity | Every request with the same upstream/key, or anonymous host, merged indefinitely | Explicit conversation hints are scoped by upstream origin/key; requests without hints get separate sessions. Existing groupings are preserved. `previous_response_id` chains and user-initiated forks are not reconstructed. |
| Reliability | Duration and percentiles; first byte mislabeled TTFT; 4xx omitted from failures | TTFB separated from first meaningful SSE output; 4xx, provider error events, and recognized incomplete streams count as failures. Historical first-byte values are relabeled. These are proxy-observed times, including upload/backpressure, not pure model compute latency. |
| WebSockets | Handshake/tunnel forwarding and bounded frame capture | Still one trace per connection. No per-generation Realtime/Responses usage, model, tool, or TTFT extraction. Binary frames retain metadata rather than full binary content. An upstream handshake failure occurs after downstream upgrade; subprotocol negotiation is not a fully transparent bridge. |
| Admin authentication | Local admin, Argon2, optional OAuth userinfo, session expiry/revocation, same-origin checks, audit events | Protected API behavior verified end to end. No per-role authorization; every admitted OAuth account has full access. An allowed user domain therefore grants those users admin access: configure a dedicated admin allowlist/provider application. OAuth is not a complete OIDC implementation with ID-token validation/PKCE. |
| Admin UI | Existing Svelte SPA, dashboard, requests/sessions, analytics, query builder, audit/plugins/system pages | Added usage/cost/tool views, attribution and completeness notices, source-request links, lazy payload loading, and bounded body rendering. UI build/type checks pass. Local headless Chromium navigation, lazy payload loading, bounded rendering, and copy behavior are tested. A production UX study and accessibility audit remain outside this pass. |

## Bugs fixed and their implications

1. **Archive persistence could lose the entire trace.** `persist_archive_segment` inserted a PostgreSQL blob referencing a segment that did not yet exist. This affected configured PostgreSQL storage and filesystem fallback. Parent metadata now precedes the blob. The transaction still includes trace, session, archive index, messages, and rollups.
2. **Filesystem append was not transaction-safe.** Overwriting a committed segment before committing its new checksum could leave old database rows pointing at changed bytes after rollback or during concurrent reads. New writes use unique immutable files containing sealed segments. Existing archive formats remain readable. Failed transactions can leave unreferenced files, but cannot overwrite committed captures.
3. **Large sessions amplified archive writes.** Every append loaded, decompressed, appended, and recompressed the whole open segment. New request bodies share a segment when their combined framed size fits the target; larger pairs use separate segments. This trades some compression across adjacent requests for bounded per-request write work. Compression, archive file writes, and read-side hashing/decompression run on blocking workers.
4. **Failure rates overstated success.** HTTP 400/401/403/429 were absent from aggregate failures. All 4xx/5xx now count, while dedicated 5xx breakdowns remain 5xx-only. JSON/SSE errors are also recognized. Legacy `proxy_error_count`/`proxy_error` labels now include stored provider/protocol errors, since they derive from the shared `error` field.
5. **TTFT meant TTFB.** The first role event or heartbeat looked like generated content. The live proxy records bounded chunk offsets/times; background parsing maps the first generated event to its chunk. Nonstreaming responses have TTFB and unknown TTFT. Output beyond the first 8192 timestamped chunks also has unknown TTFT. This does not instrument client-visible token rendering.
6. **Identity grouping could mix conversations and attribution.** A single API key became one permanent session; anonymous requests shared a host session. The fallback is now one request per unlinked session. The credential hash comes from known API-key/auth headers in deterministic priority order, not whichever sensitive header appeared first.
7. **Secret masking leaked characters.** Prefix/suffix masking could reveal short secrets completely and sliced UTF-8 unsafely. New redacted values expose only an optional safe auth scheme, optional hash, and length. Existing stored headers are not rewritten.
8. **Long transcript previews dropped the latest answer.** Taking only the first 128 messages could omit the response entirely. The preview now retains the first 64 and last 64 messages when necessary. Per-message limits still apply; the UI explicitly calls these previews.
9. **Plugin compatibility and enrichment were inconsistent.** Documentation promised a legacy `metadata` alias but the deserializer rejected it. The alias works again, and custom fields from different hooks merge under the same plugin rather than replacing all earlier fields. When no plugin is loaded, large body strings are no longer cloned just to call an empty plugin list.
10. **Session timestamps reflected persistence order.** Session first/last times and message snapshot timestamps now derive from request time, so out-of-order background workers do not rewrite chronology to database insertion time.

## Limits that should guide the next iteration

- **Memory and durability:** queued and active captured events now share a configurable allocation budget, defaulting to 256 MiB, in addition to the event-count limit. Live captures, parser/compression scratch space, and allocator overhead remain outside that budget. Overload sheds audit events while proxied requests continue; memory drops are visible in metrics and the UI. The subsequent [durable capture milestone](durable-capture.md) adds a default disk journal and idempotent replay. Synchronized records survive process restart and database write failure; in-flight and pre-sync captures can still be lost, and full journals reject new captures. See the journal guide for that boundary and deployment requirements.
- **Retention now reclaims indexed archives:** size rotation removes oldest requests, maintains rollups, and reclaims unused segments with durable file-deletion retries. Limits and intervals work through TOML or environment variables. This bounds compressed payloads asynchronously, not total disk usage; database metadata/WAL, operational logs, and unindexed files left by failed writes remain outside the limit. A shared, stable filesystem root is required across replicas.
- **1M-token histories are still full snapshots:** metadata queries avoid bodies, but JSON parsing and full body viewing require whole captured payloads in memory. Repeated prompt prefixes are stored again for each request. Content-addressed chunks or message trees could reduce this; they must preserve branches, edits, tool correlation, and exact raw audit evidence. Do not deduplicate merely by message text.
- **Horizontal scaling needs archive planning:** local filesystem archives are not automatically shared between replicas. Use a shared persistent volume or PostgreSQL storage until an object-storage backend exists. Back up the database and archive content together.
- **Billing needs explicit contracts:** reported usage may be absent or partial; configured prices are estimates and do not represent quota balance, refunds, negotiated discounts, cache TTL tiers, or provider invoices. Persisting the price/version alongside each estimate would improve auditability. Aggregates are lookback windows, not calendar-month ledgers. There is no budget enforcement or user self-service.
- **Attribution needs a trusted source:** clients can choose conversation metadata. A gateway identity lookup/plugin must establish user identity. Shared API keys and missing credential hashes weaken isolation; session hints alone are not user authentication. Identity plugin errors leave unknown users, and failed lookups are not retried later.
- **Admin controls:** there is one access level. Add RBAC if investigators and statistics viewers need different permissions. Audit events cover authentication/admin actions, not every body read/export. There is no built-in personal-use classifier or policy adjudication workflow.
- **WebSocket protocol modeling:** generic forwarding is useful, but connection-level statistics do not meet per-response accounting for Realtime or Responses over WebSocket. Model the protocol events separately, including cancellation, multiple responses, and usage snapshots.
- **Large searches/exports:** list pagination uses offsets and bounded exports return a page only. Full-session exports, keyset pagination, full transcript retrieval, and server-side text search remain future work. The UI bounds raw JSON traversal and rendering; explicit copying still serializes the complete captured object.

## Configuration and migration

See [plugin-http.md](plugin-http.md) for the optional identity lookup ABI and `llmtrace.example.toml` for illustrative pricing. No real identity endpoint or price table was configured during this audit.

Migration `004_llm_usage.sql` adds fields/indexes, relabels historical timing values, and recalculates existing error rollups. It updates historical rows and can take time on a large database; assess migration duration on a copy before rollout. It does not reparse old payloads, regroup old sessions, or remove old redacted-header fragments. Deploy the frontend and backend together because the UI expects the new response fields.

## Verification

The original baseline passed 313 Rust unit tests and 35 frontend tests. Added tests cover cumulative and missing usage, SSE framing, partial UTF-8 tails, tool fragments and final snapshots, provider errors, bounded previews, credential hashing/redaction, session scoping, cost estimates, and output timing.

The audit and rotation pass verified 335 Rust unit tests and eight integration tests (343 total), 36 frontend tests, Svelte checks with zero warnings/errors, the frontend production build, Clippy with warnings denied, and the embedded migration command against PostgreSQL 16, including migration `005_archive_rotation.sql`. The subsequent performance pass expanded this to 349 functional Rust tests, three opt-in release performance tests, and 41 frontend tests; see its report below. Archive integration fixtures include approximately 5 MB request bodies containing one million repeated words; this is a synthetic storage fixture, not a model tokenizer or throughput benchmark.

The PostgreSQL integration suite creates isolated databases. It exercises synthetic large request bodies, both archive backends, filesystem fallback, reading old captures after subsequent writes, capture flags, usage/session/user aggregates, and structured filters. A full-router test proxies delayed SSE through a real local upstream, verifies exact forwarded bytes, persists usage/pricing, and checks unauthenticated denial, admin login, protected retrieval, and cross-origin rejection. WASM HTTP tests use a local mock identity server to verify lookup, redirects, and timeouts.

Size-retention tests cover file/environment precedence and validation, exact thresholds, oldest-first eviction across mixed backends, legacy shared segments and inline bodies, retained transcript readability, rollup consistency, disabled rotation, rollback, missing files, durable deletion retry, pruner coordination, and sessions being written concurrently. File-deletion jobs are retried by a fresh maintenance invocation; abrupt process termination and storage-device failure have not been fault-injected.
